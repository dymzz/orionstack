# 文档库标准目录说明

## 1. 目录目标

本目录用于集中维护 **第一阶段企业文档库标准文档**。

这些文档不是系统实现说明，也不是业务操作手册，而是用于统一以下事项的标准依据：

1. 企业文档在第一阶段按什么维度分类
2. 各业务域应收哪些类型的标准文档
3. 文档清洗、归类、入库时应遵循什么最小字段约束
4. 文档生命周期与访问范围应如何做轻量标记
5. 后续新增业务域时，如何沿用同一套知识库标准

---

## 2. 当前使用范围

本目录服务于第一阶段的知识库建设，当前适用于：

- FAQ / 业务知识问答主链路
- 文档清洗前的归类标准
- 文档入库前的元数据补齐标准
- 文档切块与 citation 回源前的最小来源标记标准

当前阶段，这些文档只作为 **知识库标准来源** 使用，不承担以下职责：

- 不承担系统运行时权限判断
- 不承担复杂内容治理流程
- 不承担企业正式档案管理系统职责
- 不承担独立文控平台职责

---

## 3. 当前目录中的文档类型

本目录当前建议只放以下两类文档：

### 3.1 通用标准文档

用于冻结第一阶段全局适用的文档库规则，例如：

- `phase1_document_library_fields_freeze.md`

这类文档主要回答：

- 第一阶段企业文档库最小字段有哪些
- 文档最小分类维度是什么
- 生命周期和访问范围如何标记

### 3.2 业务域标准文档

用于定义某一个业务域的文档库边界与收录规则，例如：

- `domain_hr_library_v1.md`
- `domain_finance_library_v1.md`
- `domain_it_library_v1.md`

这类文档主要回答：

- 当前业务域属于什么范围
- 该业务域常见文档类型有哪些
- 哪些文档适合纳入第一阶段知识库
- 哪些文档当前不纳入
- 访问范围建议如何标记

## 5. 第一阶段统一分类基线

本目录下所有业务域文档，应统一遵循第一阶段最小字段基线。

至少围绕以下维度进行定义：

- `business_domain`
- `document_type`
- `source_type`
- `lifecycle_status`
- `access_scope`

其中：

### 5.1 business_domain
表示业务域，例如：

- `hr`
- `finance`
- `it`

### 5.2 document_type
表示文档类型，例如：

- `policy`
- `process`
- `faq`
- `guide`
- `notice`
- `template`
- `reference`

### 5.3 source_type
表示来源类型，例如：

- `upload`
- `manual_faq`
- `imported`

### 5.4 lifecycle_status
表示生命周期状态，例如：

- `draft`
- `active`
- `deprecated`
- `archived`

### 5.5 access_scope
表示轻量访问范围标记，例如：

- `public`
- `internal`
- `restricted`
- `team`

说明：

当前阶段只做轻量访问范围标记，不做真正的 RBAC / ABAC 权限系统。

## 6. 这些文档如何参与文档清洗入库

后续做文档清洗与入库时，应优先参考本目录中的标准文档，完成以下动作：

1. 确定当前文档属于哪个业务域
2. 确定当前文档属于哪种文档类型
3. 判断当前文档是否在第一阶段收录范围内
4. 为文档补齐最小元数据
5. 为后续 chunking 与 citation 回源保留来源信息

也就是说，本目录中的文档主要用于回答：

**“这份文档应不应该入库，以及应以什么标准入库。”**

---

## 7. 当前阶段不做的事

本目录当前明确不承担以下任务：

1. 不输出企业完整文档治理规范
2. 不定义复杂审批流
3. 不设计细粒度权限矩阵
4. 不设计企业档案管理制度
5. 不对所有历史文档做一次性全量归档标准化
6. 不替代系统设计文档或运行文档

---

## 8. 维护规则

新增业务域文档时，应遵循以下规则：

1. 新业务域文档必须放在本目录下
2. 必须沿用统一命名方式：`domain_<业务域>_library_v1.md`
3. 必须遵循第一阶段最小字段基线
4. 必须写清楚“纳入范围 / 不纳入范围 / 推荐文档类型 / 访问范围建议”
5. 不得在业务域文档中单独扩展出复杂权限体系或平台治理规则

---

## 9. 一句话总结

本目录是 **第一阶段知识库文档清洗与入库的标准来源目录**。

它的目标不是把企业所有文档管理问题一次解决，而是为当前知识问答系统提供：

- 可执行的文档分类基线
- 可复用的业务域标准
- 可落地的入库判断依据
