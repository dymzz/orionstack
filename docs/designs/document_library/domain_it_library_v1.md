# 第一阶段业务域文档库说明：IT

## 1. 文档目标

本文档用于定义第一阶段企业知识库中 **IT 业务域** 的收录范围、文档类型边界、最小元数据要求与访问范围建议。

本文档服务于以下目标：

1. 为 IT 业务域文档清洗提供统一分类依据
2. 为 IT 业务域文档入库提供最小字段参考
3. 为后续问答检索与 citation 回源提供前置标准
4. 控制第一阶段 IT 文档库范围，避免一次性做成全量 IT 运维平台

---

## 2. 业务域定义

### 2.1 business_domain

当前业务域固定为：

```text
it
```

### 2.2 当前业务域含义

第一阶段中的 `it` 业务域，主要指企业内部通用 IT 支持与使用类知识，包括：

- 账号与权限的常见申请说明
- 网络、设备、办公软件使用说明
- 常见 IT 故障处理 FAQ
- 标准化 IT 服务流程说明
- IT 服务台常见通知与指引

### 2.3 当前业务域不包括

当前阶段，`it` 业务域不包括以下内容：

- 深度基础设施运维手册
- 复杂网络拓扑与安全架构文档
- 高敏感漏洞处置细节
- 生产系统运维应急预案细节
- 高风险系统访问策略配置细节
- 不适合在通用问答中直接暴露的内部安全内容

也就是说，第一阶段 IT 文档库优先面向：

**企业员工常见 IT 使用与支持问答。**

---

## 3. 推荐纳入的文档类型

第一阶段，IT 业务域建议优先纳入以下文档类型。

### 3.1 policy

适合纳入的制度类文档包括：

- 办公设备使用规范
- 企业账号使用规范
- 密码与基本安全要求说明
- 邮件、网盘、协作工具使用规范

说明：

此类文档适合用于回答“能不能做”“要求是什么”这类问题。

### 3.2 process

适合纳入的流程类文档包括：

- 账号开通流程
- 权限申请流程
- 设备申领流程
- 故障报修流程
- VPN 开通流程

说明：

此类文档适合用于回答“怎么申请”“在哪提交”“流程是什么”这类问题。

### 3.3 faq

适合纳入的 FAQ 类文档包括：

- 忘记密码怎么办
- 无法连接办公网络怎么办
- 邮箱登录失败怎么办
- VPN 无法连接怎么办
- 打印机不可用怎么办
- 公司电脑如何更换设备

说明：

FAQ 是第一阶段 IT 业务域最推荐优先沉淀的内容类型。

### 3.4 guide

适合纳入的操作指引类文档包括：

- 企业邮箱配置指南
- VPN 使用指南
- 协作工具使用指南
- 会议软件安装与使用说明
- 文件共享工具使用说明

说明：

此类文档适合用于回答“如何配置”“如何操作”“如何查看”这类问题。

### 3.5 notice

适合纳入的通知类文档包括：

- IT 服务中断通知
- 计划维护通知
- 系统升级通知
- 工具迁移通知

说明：

通知类文档可纳入，但应配合生命周期状态使用，避免陈旧通知污染检索结果。

### 3.6 template

适合纳入的模板类文档包括：

- 权限申请模板
- 设备申请模板
- 工单提交模板

说明：

模板类文档适合用于回答“该填什么”“用哪个模板”这类问题。

### 3.7 reference

适合纳入的参考类文档包括：

- IT 服务目录
- 常用系统入口清单
- 支持联系方式说明
- 企业常用软件列表

说明：

此类文档适合作为 citation 支撑与基础参考内容。

---

## 4. 当前阶段不建议纳入的文档

第一阶段，以下 IT 文档不建议直接纳入当前通用知识库：

1. 高敏感系统运维手册
2. 生产环境配置明细
3. 高危安全漏洞处理文档
4. 网络访问控制策略明细
5. 服务器、数据库、密钥等敏感资产清单
6. 高风险应急处置剧本
7. 不适合通过通用员工问答直接暴露的安全内容

说明：

这些内容即使未来需要纳入，也应进入更严格的受限知识域，而不是第一阶段通用 IT 文档库。

---

## 5. 第一阶段最小元数据建议

对 IT 业务域文档，建议至少补齐以下字段：

- `document_id`
- `title`
- `business_domain=it`
- `document_type`
- `source_type`
- `lifecycle_status`
- `access_scope`
- `source_locator`
- `created_at`
- `updated_at`

如文档后续需要参与 citation 回源，还建议保留：

- `page_number`
- `paragraph_id`
- `chunk_id`

---

## 6. lifecycle_status 建议

IT 文档建议统一使用以下生命周期状态：

- `draft`
- `active`
- `deprecated`
- `archived`

说明：

### 6.1 active
默认检索优先命中状态。

### 6.2 deprecated
表示内容仍可参考，但不应作为默认最佳答案来源。

### 6.3 archived
表示仅保留记录，不应参与默认检索。

对于通知类与指南类内容，生命周期状态尤其重要。

---

## 7. access_scope 建议

第一阶段对 IT 文档只做轻量访问范围标记。

建议使用：

- `public`
- `internal`
- `restricted`
- `team`

### 7.1 推荐用法

#### public
适用于可公开给全员查看的基础 IT 指南与 FAQ。

例如：

- 如何连接办公网络
- 如何重置密码
- 如何使用企业邮箱

#### internal
适用于企业内部员工可见的一般 IT 文档。

例如：

- 设备申领流程
- 权限申请流程
- 服务目录说明

#### restricted
适用于存在一定敏感性的 IT 文档，但当前阶段仍只作为标记，不做复杂权限判断。

例如：

- 特定系统使用说明
- 部分内部管理指引

#### team
适用于特定 IT 小组或特定部门相关文档。

例如：

- 桌面支持团队专用流程
- 某区域办公室设备运维指引

说明：

第一阶段这里只做 `access_scope` 标记，不做实际细粒度权限拦截。

---

## 8. source_type 建议

IT 业务域当前建议支持以下来源：

- `upload`
- `manual_faq`
- `imported`

### 8.1 upload
适用于人工上传的操作手册、指南、通知等文档。

### 8.2 manual_faq
适用于直接人工整理的常见问题问答对。

### 8.3 imported
适用于从现有知识库、工单系统或历史资料中导入的内容。

---

## 9. 文档清洗建议

在正式入库前，IT 业务域文档建议至少做以下清洗：

1. 去除重复页眉页脚
2. 去除明显无意义格式噪声
3. 统一标题与层级结构
4. 补齐最小元数据
5. 判断是否属于高敏感内容
6. 对过时通知和旧流程文档做生命周期标记
7. 确保切块后仍保留可回源定位信息

---

## 10. 推荐优先入库顺序

第一阶段，IT 业务域建议按以下顺序入库：

### 第一优先级
- FAQ
- guide
- process

### 第二优先级
- policy
- reference

### 第三优先级
- notice
- template

原因：

FAQ、guide、process 最直接支撑员工高频 IT 问答，是第一阶段 ROI 最高的内容。

---

## 11. 问答场景示例

以下问题通常适合由 `it` 业务域知识库回答：

- 如何重置企业账号密码？
- 如何申请 VPN？
- 公司电脑坏了怎么报修？
- 如何配置企业邮箱？
- 无法连接打印机怎么办？
- IT 服务工单在哪里提交？

以下问题当前不适合由第一阶段 `it` 业务域知识库直接回答：

- 防火墙策略怎么改？
- 生产数据库凭据是什么？
- 内网访问控制规则明细有哪些？
- 某敏感系统的管理员登录方式是什么？

---

## 12. 当前阶段结论

第一阶段 IT 业务域文档库应聚焦：

- 企业员工常见 IT 问答
- 标准操作指引
- 标准申请流程
- 基础制度说明
- 可回源的引用支撑内容

不应扩展为：

- 完整 IT 运维知识平台
- 安全策略细节库
- 敏感资产知识库
- 细粒度权限治理系统

一句话总结：

**第一阶段的 IT 业务域文档库，目标是提升企业内部常见 IT 支持问答的可检索性与可回答性，而不是承载高敏感运维与安全知识。**
