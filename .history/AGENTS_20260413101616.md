# Task: Make documented boundaries become the default execution path

You are not redesigning the architecture.
You are implementing the documented Phase 1 boundary as the **default runtime behavior**.

## Core requirement

The repository already defines the current product boundary:

- Phase 1: knowledge assistant MVP
- main path first
- thin abstraction first
- no heavy framework-first chain for simple QA
- prioritize direct, controllable, traceable document QA

Your task is to make that boundary become the **default execution path**, not just documentation.

## Problem to fix

Current behavior violates the documented boundary:

- simple FAQ / procedure questions still go through heavier retrieval post-processing
- default runtime behavior is too complex for simple document QA
- this causes high latency, token waste, and irrelevant topic expansion

Example:
asking `如何请假` should return only the leave procedure from the leave FAQ entry.
It must not expand into unrelated topics such as password reset, software install, reimbursement, meeting room booking, employee benefits, etc.

## Required default execution rule

For **simple FAQ / single-topic / direct procedure questions**, the default path must be:

`user question`
-> `optional minimal LLM query rewrite for retrieval terms only`
-> `embedding retrieval`
-> `top 1-3 chunks`
-> `direct answer from those chunks`

This must become the default execution path for this class of questions.

## Explicit runtime constraints

For the simple FAQ path:

- rerank must be OFF by default
- model-based evidence extraction must be OFF by default
- no candidate-topic enumeration
- no extra post-retrieval LLM filtering chain
- no long multi-stage reasoning chain

If needed, complex retrieval enhancements may exist elsewhere, but they must NOT be the default path for simple FAQ questions.

## What counts as a simple FAQ / procedure question

Treat questions like these as simple-path questions:

- 如何请假
- 怎么请假
- 病假怎么申请
- 事假怎么申请
- 年假余额在哪里看
- 会议室如何预订
- 报销多久到账

Common traits:

- answer is likely in one FAQ entry / one short section
- single topic
- direct procedural or factual lookup
- no multi-document synthesis needed
