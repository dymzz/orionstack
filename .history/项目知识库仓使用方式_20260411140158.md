# 项目知识库仓使用方式

## 当前默认策略

当前阶段默认使用：

```powershell
.\scripts\kb.ps1

## 1. 初始化知识库路径

```powershell
.\scripts\load-kb-context.ps1 -KbPath "D:\workspace\python\orionstack-kb" -PersistUser
```

执行后会设置 `ORIONSTACK_KB_PATH`，后续脚本可以直接复用。

## 2. 读取默认 4 个入口文件

```powershell
.\scripts\load-kb-context.ps1
```

默认读取：

- `context/project_index.md`
- `context/current_phase.md`
- `context/frozen_contracts.md`
- `context/ai_entry.md`

## 3. 读取并检索关键词

```powershell
.\scripts\load-kb-context.ps1 -Query "reindex|workflow"
```

## 4. 只检索设计文档

设计文档固定目录：

`D:\workspace\python\orionstack-kb\docs\designs`

```powershell
.\scripts\load-kb-context.ps1 -DesignsOnly -Query "upload"
```

## 5. 启动一次 KB 同步流程

kb.ps1 是统一入口，当前默认行为是简易同步。
start-kb-sync.ps1 是增强入口，不是日常默认入口

日常推荐优先使用：

```powershell
.\scripts\kb.ps1
```

这是一个简化入口，会自动进入易用模式，只问最少的一组信息。

复杂场景或调试时再使用：

```powershell
.\scripts\start-kb-sync.ps1
```

这个脚本会：

- 自动定位知识库仓
- 输出主工程仓 `ref_main_commit` / `ref_main_pr`
- 列出当前改动文件
- 给出建议同步的 KB 文档清单
- 提醒 `docs/designs/` 和 `repomix/` 的同步位置
- 可同时生成主仓和知识库仓的 commit message 草稿

只看清单、不读取上下文：

```powershell
.\scripts\start-kb-sync.ps1 -NoRead
```

带关键词一起检索：

```powershell
.\scripts\start-kb-sync.ps1 -Query "reindex|workflow"
```

交互式填写版本号和提交信息：

```powershell
.\scripts\start-kb-sync.ps1 -Interactive
```

易用模式：

```powershell
.\scripts\start-kb-sync.ps1 -Easy
```

## 6. 新建设计文档

```powershell
.\scripts\start-kb-sync.ps1 -NoRead -NewDesign "workflow reindex"
```

会基于知识库模板自动创建到：

`D:\workspace\python\orionstack-kb\docs\designs`

生成文件名格式遵循：

`design_<topic>_vYYYYMMDD.md`

## 7. 更新 repomix

repomix 产物位置：

- `D:\workspace\python\orionstack-kb\repomix\main_repo\repomix-output.xml`
- `D:\workspace\python\orionstack-kb\repomix\frontend_repo\repomix-output.xml`

如果本机已经安装 `repomix`，可以执行：

```powershell
.\scripts\start-kb-sync.ps1 -NoRead -RunRepomix
```

如果遇到权限报错，直接在本机普通终端重跑即可。

## 8. 提交前引用主工程仓信息

```powershell
.\scripts\print-main-ref.ps1
```

输出结果可直接用于知识库仓提交说明中的：

- `ref_main_commit`
- `ref_main_pr`

## 9. 交互式版本更新和 git 提交

如果希望把版本更新和 git 提交整合在一起，推荐使用：

```powershell
.\scripts\kb.ps1
```

易用模式默认只问这些：

- 是否修改 `pyproject.toml` 版本
- 是否现在提交主仓
- 主仓 commit subject
- 主仓 `ref-kb`
- 主仓 `updated`
- 是否 `git add -A`
- 是否现在执行 `git commit`
- 是否生成知识库仓 commit 草稿
- 知识库仓 commit subject
- 知识库仓 `updated`

完整交互模式会进一步询问：

- 主仓 commit subject
- 主仓 `ref-kb`
- 主仓 `updated`
- 是否执行 `git add -A`
- 是否立即执行 `git commit`
- 是否生成知识库仓 commit 草稿
- 知识库仓 commit subject
- 知识库仓 `updated`
- 是否覆盖 `ref-main`

也可以非交互直接传参：

```powershell
.\scripts\start-kb-sync.ps1 -NoRead -Version "0.1.1" -CommitChanges -StageAll -CommitSubject "chore: bootstrap repo" -RefKb "context/project_index.md" -UpdatedKb "project_index + repo_map" -KbCommitSubject "docs: sync bootstrap repo from main" -KbUpdated "project_index + repo_map + design doc"
```

第一次成功提交后，脚本会重新读取：

- `ref_main_commit`
- `ref_main_pr`

此时 `HEAD` 就不再是空状态，后续同步时会显示真实 commit。

## 10. 主仓和知识库仓 commit 草稿

`commit message 草稿` 指的是脚本先把准备提交的 message 预览出来给你确认，再决定是否真的执行 `git commit`。

主仓示例：

```text
chore: bootstrap repo

version: 0.1.1
ref-kb: context/project_index.md
updated: project_index + repo_map
```

知识库仓示例：

```text
docs: sync bootstrap repo from main

ref-main: 3494582af6351f8d8bdd00081eb5567c6b71d243
updated: project_index + repo_map + design doc
```

如果主仓在当前脚本运行中刚完成提交，知识库仓草稿会自动使用最新的 `ref_main_commit`。

这样做的好处是：

- 先检查格式对不对
- 先确认 `ref-kb` 和 `updated` 有没有写错
- 在真正提交前还能取消
