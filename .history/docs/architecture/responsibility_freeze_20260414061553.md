# OrionStack 职责冻结表（当前阶段）

## 1. 文档目标

本文档用于冻结当前阶段中以下四层的职责边界：

- skill
- workflow
- integrations
- 外部自动化编排

目标不是扩展功能描述，而是明确：

- 每层负责什么
- 每层明确不做什么
- 层与层之间如何协作
- 当前阶段哪些能力不进入主链路

本文件作为当前阶段的边界约束文档，优先级高于临时讨论结论。

---

## 2. 当前阶段总原则

当前阶段遵循以下总原则：

1. 主链路优先
2. 薄抽象优先
3. 职责边界优先
4. 平台化后置
5. 执行型能力后置
6. 旧系统持续存在前提下非侵入接入

当前主链路为：

**文档上传 → 文档解析 → 索引构建 → 检索召回 → 问答生成 → 引用返回 → 历史记录与反馈**

复杂 Tool 编排、跨系统执行、自动审批等能力，不进入首期主链路。

---

## 3. 冻结对象总览

### 3.1 skill
定位为：**业务入口的薄路由层**

### 3.2 workflow
定位为：**应用内多步骤链路编排层**

### 3.3 integrations
定位为：**旧系统接入 / 外部系统适配 / 工具封装边界层**

### 3.4 外部自动化编排
定位为：**跨系统自动化执行包装层**

---

## 4. skill 职责冻结

### 4.1 定位

skill 是入口路由壳。

它的职责是把请求送到正确的处理链，而不是自己完成全部业务处理。

### 4.2 应做

- 识别业务域
- 选择 handler
- 决定进入哪条固定处理链
- 决定走直返、规则判断、检索兜底还是 workflow
- 在低置信度时做降级去向判断

### 4.3 明确不做

skill 不做以下内容：

- 不做统一意图层真源
- 不做自然语言深度归一真源
- 不做 FAQ / 卡片内容维护
- 不做检索召回实现
- 不做 rerank 细节
- 不做最终答案生成
- 不做多步骤状态推进
- 不做外部系统调用
- 不做自动执行
- 不做审计真源
- 不做历史记录真源
- 不做权限判断真源

### 4.4 一句话冻结

**skill 只回答“去哪”，不回答“如何完整做完”。**

---

## 5. workflow 职责冻结

### 5.1 定位

workflow 是应用内多步骤链路编排层。

它负责组织内部步骤、维护状态边界、承接复杂场景的链路推进。

### 5.2 应做

- 多步骤链路编排
- 节点边界组织
- 状态推进
- 阶段性上下文传递
- 人工确认前后的链路承接
- 复杂场景下的应用内 orchestrate

### 5.3 明确不做

workflow 不做以下内容：

- 不做 API 接入层职责
- 不做数据库真源
- 不做仓储真源
- 不做统一意图层真源
- 不做旧系统接入适配
- 不做外部系统协议处理
- 不做知识层真源
- 不做最终执行系统
- 不替代旧 ERP / OA / 权限系统
- 不承担系统级自动审批执行
- 不将 LangGraph 扩散到接口契约层、数据真源层、旧系统适配层与主链路执行层

### 5.4 一句话冻结

**workflow 只负责“应用内如何推进步骤”，不负责“外部系统如何成为执行真源”。**

---

## 6. integrations 职责冻结

### 6.1 定位

integrations 是旧系统接入与外部系统适配边界层。

它负责把系统接得上、调得通、协议隔离清楚。

### 6.2 应做

- 旧 ERP / OA / 权限系统适配
- 外部系统 API / SDK / Tool 封装
- gateway / adapter 边界维护
- 外部认证、协议、调用细节隔离
- 执行动作的技术接入

### 6.3 明确不做

integrations 不做以下内容：

- 不做统一意图层
- 不做 skill 路由
- 不做业务规则真源
- 不做流程主控
- 不做工作流状态机
- 不做知识检索主链
- 不做最终答案生成
- 不做引用真源
- 不做审计真源
- 不做历史记录真源
- 不被框架接管成“框架驱动的执行中心”

### 6.4 一句话冻结

**integrations 只负责“接得上、调得通”，不负责“业务上该不该调、何时调、为什么调”。**

---

## 7. 外部自动化编排职责冻结

### 7.1 定位

外部自动化编排是跨系统自动化执行包装层。

典型形态包括：
- webhook 编排
- 定时任务
- 通知链
- 回调链
- 跨 SaaS / OA / ERP 串联

### 7.2 应做

- 跨系统触发器组织
- webhook / schedule / callback 串联
- 通知、审批后续动作自动化
- 节点式外部自动化流程包装

### 7.3 明确不做

外部自动化编排不做以下内容：

- 不做统一意图层
- 不做 skill 真源
- 不做知识检索真源
- 不做证据与引用真源
- 不做业务规则真源
- 不做权限真源
- 不做审计真源
- 不替代旧系统成为事实来源
- 不替代内部 workflow 成为应用内状态真源
- 不进入当前阶段主链路

### 7.4 一句话冻结

**外部自动化编排只负责“把既定动作自动串起来”，不负责“定义系统内部真相”。**

---

## 8. 层间关系冻结

### 8.1 skill → workflow

允许：
- skill 判断当前场景需要复杂链路时，将请求送入 workflow

不允许：
- skill 自己膨胀成多步骤状态机
- skill 自己承接长流程推进
- skill 自己承接人工确认后的状态恢复

### 8.2 workflow → integrations

允许：
- workflow 在需要调用外部能力时，通过 integrations 完成外部系统访问

不允许：
- workflow 直接内嵌旧系统适配细节
- workflow 直接承担协议转换、认证、SDK 绑定等 adapter 工作

### 8.3 integrations → 外部自动化编排

允许：
- 将已有 API / tool adapter 暴露为未来自动化编排可调用边界

不允许：
- 让外部自动化编排反向定义内部业务规则
- 让自动化平台成为系统内核真源

### 8.4 外部自动化编排 → 主链路

允许：
- 在未来复杂跨系统场景中作为自动化包装层接入

不允许：
- 当前替代知识问答主链
- 当前替代统一意图层
- 当前替代引用与反馈闭环

---

## 9. 当前阶段明确不进入主线的内容

以下能力当前阶段明确不进入主链路：

- 自动审批
- 自动写入旧系统
- 跨系统复杂 Tool 编排
- 外部自动化编排平台接管核心链路
- 以 LangGraph / LangChain 接管主执行层
- 多 Agent 复杂框架化扩展

---

## 10. 当前阶段推荐主线

当前阶段推荐主线固定为：

**统一意图层 → 薄 skill 路由 → 域内确定性模块 / 检索兜底 → 引用返回 → 历史与反馈**

其中：

- skill 只做薄路由
- workflow 当前保持轻量
- integrations 保持非侵入接入
- 外部自动化编排不进入主链路

---

## 11. 最终冻结版一句话

- **skill**：只做路由，不做重处理
- **workflow**：只做应用内编排，不做外部执行真源
- **integrations**：只做接入适配，不做业务判断
- **外部自动化编排**：只做跨系统自动化包装，不做系统核心真源
